# Secondary motion: implementation and validation plan

## Scope and inspection

Godot 4.4.1, GL Compatibility, native Android export. The existing CC0 avatar and its skeleton remain unchanged. Inspection of the imported avatar's skeleton found 16 hair joints, 18 skirt joints and 4 sleeve joints (excluding end markers), plus four bust joints which are **not simulated**. The avatar has no independent ribbon, bow or accessory bones; only explicitly named `J_Sec_` accessory joints would be eligible on a compatible future rig. No accessory was invented or attached to the existing model.

## Solver

Each eligible joint uses two reused damped angular spring objects. Per-joint parent translation, velocity, filtered acceleration and gravity direction drive bounded local angular offsets, with small deterministic parameter differences across chains. Solver steps are capped at 1/60 s, long stalls and teleports reset velocity inputs, and damping settles the motion. Secondary rotation is composed after the authored retarget and does not alter its source rig. Hair, skirt and sleeve limits are intentionally small to retain the original silhouette and coverage; bust bones are excluded. The system does not modify base walking, attack or dodge clips and has no separate jump or run gameplay state to test in this prototype.

Two points along each skirt child-bone segment are checked against four approximate upper/lower-leg capsules, with a conservative bounded rotational sweep. If an animated rest point is already inside a proxy it is left alone; otherwise the secondary rotation is limited before a sampled point enters a capsule. This is **not mesh collision**: vertices between samples, existing authored-pose penetration, numerical edge cases in the angular sweep and skirt topology may still clip. Reliable cloth/leg collision and outfit coverage require artist-authored collision proxies, skinning review and tests across animations on the final rig.

`secondary_motion/quality` in `project.godot` or `player.secondary_motion.set_quality(level)` accepts 0 (off), 1 (root joints only), 2 (all eligible joints, default). Switching fades spring influence over 0.25 seconds; off and reduced tiers stop work for inactive chains. The deploy and pause menus expose and persist these settings along with reduced/full VFX. The shadow-dodge's separate reusable avatar instance remains a notable render and memory cost outside this solver.

## Validation

Headless category tests check separate hair/skirt/sleeve acceleration response, bounds, settling, long stalls, animation ownership, leg-proxy math, quality switching and exclusion of bust joints; the combat and authored-retarget tests remain in CI. Software-rendered before/after move, combo and dodge previews permit a qualitative comparison. The visible difference may be subtle at gameplay camera scale; no claim of animator-quality movement or zero clipping is made.

The `Native Android emulator smoke` workflow (manual or on workflow changes) builds a private debug APK from the checked-out commit, starts it in API 30 x86_64 Android with software ANGLE, exercises input and captures an image, Android `gfxinfo` data and an opt-in Godot debug timing sample. The workflow enables `secondary_motion/profile_debug` only in the temporary export; it remains off in the project. It **does not publish an APK**. Emulator software rendering and debug builds cannot establish sustained 60 FPS, GPU cost, real mobile touch behavior or battery/thermal performance. For acceptance, profile the same representative walk/attack/dodge sequence at each quality level on physical low/mid/high Android devices, record build/OS/device/GPU and median/p95/p99 frame times, warm up, run several minutes and inspect clipping and coverage from multiple angles.

### Recorded checks (2026-11-21)

- Native validation run `44938253396` passed the combat smoke, five-clip/22-bone retarget, secondary/VFX and secondary category/quality/capsule tests. Software-rendered walk, combo and dodge were inspected against the earlier pass: changes are restrained and are not strong evidence of animator-quality motion or mesh-level collision safety.
- Android run `44938253406` exported the same code as a debug build, installed and ran it on API 30 x86_64 emulator, 640×320, ANGLE/SwiftShader software graphics. Gameplay was visible after scripted movement, attack and dodge taps. Godot's opt-in sample reported 105 wall-frame intervals averaging 85.67 ms, p95 153.14 ms; 601 spring updates averaged 557.9 µs with a 38,626 µs maximum. Frame samples cover approximately the 2–10 second period after starting play; solver samples include the warm-up. The emulator is heavily software-rendered, debug-instrumented, and not representative of a physical GPU or stable device performance. Android `gfxinfo` reported zero View-system frames for this game surface and cannot be used as an FPS measurement. No before-run timing or comparable physical-phone profile was captured. The 60 FPS target is **not verified**, and no APK was published.

The 2026-11-22 pass adds authored CC0 sword-combo clips, multi-angle close-up capture, sweep tests and persistent quality controls. Close-up software renders were reviewed but are not proof of complete outfit coverage. The sampled leg capsules are engineering approximations, not artist-tuned cloth proxies; a real-device/animator pass is still required.

The latest pass enables the authored formal walk and sword dash, tests the second retarget source's limb directions, and uses conservative rotation sweeps with a narrow-crossing regression. Matching software close-ups compare the old and new motions, but the proxy remains bone-based and cannot certify mesh coverage. See `ANDROID_PROFILING.md` for the latest debug-emulator tier and shadow-on/off samples; physical-device and artist review are still outstanding.
